# YggGuard для Linux · AppImage 0.2.0

Первый Linux-клиент: центральная бирюзовая кнопка подключения, плюс для добавления прокси, сохранённые профили и журнал. В AppImage включены **Yggdrasil, sing-box, GUI и библиотеки Qt** — устанавливать Yggdrasil, Throne или sing-box на компьютер не нужно.

## Запуск

Файл: `dist/YggGuard-0.2.0-x86_64.AppImage`.

```bash
chmod +x YggGuard-0.2.0-x86_64.AppImage
./YggGuard-0.2.0-x86_64.AppImage
```

Если FUSE недоступен:

```bash
./YggGuard-0.2.0-x86_64.AppImage --appimage-extract-and-run
```

Запускайте от обычного пользователя, **не через sudo**. При нажатии «Подключить» системное окно polkit запросит права администратора для сетевого компонента.

Системные требования:

- Linux x86_64 с TUN (`/dev/net/tun`) и обычным графическим сеансом X11/Wayland;
- polkit (`pkexec`) и запущенный агент авторизации рабочего стола;
- nftables (`nft`) для защиты входящих соединений на интерфейсе Yggdrasil;
- системные корневые сертификаты (`ca-certificates`).

Для Debian/Ubuntu:

```bash
sudo apt install pkexec nftables ca-certificates
```

Для Arch/CachyOS:

```bash
sudo pacman -S --needed polkit nftables ca-certificates
```

Первая локальная сборка сделана на текущем CachyOS с Qt 6.12 и включает библиотеки хоста. Это **тестовая сборка для современных настольных Linux**, не обещание совместимости со всеми старыми дистрибутивами/процессорами. Для широкой совместимости пересоберите на старейшей поддерживаемой системе (например Ubuntu 22.04). Встроенный бинарник Yggdrasil в этой локальной сборке требует glibc >= 2.34 на хосте; GUI использует свой согласованный комплект загрузчика и библиотек.

## Добавление сервера

1. Нажмите **+**.
2. Введите название, полный IPv6 VPS **в сети Yggdrasil** и порт.
3. `1080` — обычный выход с публичного IP VPS; `2080` — через Tor.
4. Поле пиров содержит исходный пир из нашей предыдущей настройки. Его можно заменить или добавить другие `tcp://`, `tls://`, `quic://` URI — по одному на строку. Нужен хотя бы один доступный пир, это не адрес HTTP-прокси и не IP VPS из поля выше.
5. Нажмите «Добавить», выберите профиль и нажмите центральную кнопку.
6. Подтвердите системный запрос прав. Первое соединение может занимать до двух минут.

Перед включением VPN клиент проверяет доступ к HTTPS через выбранный прокси. Для порта 2080 дополнительно проверяется, что выход определяется как Tor. При ошибке см. «Журнал подключения».

Если сервер использует allowlist, разрешите **адрес встроенного узла приложения**, а не адрес отдельно установленного Yggdrasil. Адрес узла появляется в журнале Yggdrasil при подключении. При стандартном серверном `Allow 200::/7` менять ничего не нужно.

Профили и постоянный ключ узла хранятся в `~/.local/share/YggGuard/YggGuard/profiles.json` (или соответствующем XDG_DATA_HOME), файл доступен только владельцу. Поэтому адрес узла сохраняется между запусками. Не публикуйте этот файл: он содержит приватный ключ.

## Маршрут и отключение

```text
приложения → sing-box TUN → HTTP CONNECT → Yggdrasil → Tinyproxy VPS → интернет / Tor
```

Yggdrasil и sing-box включены в AppImage как отдельные исполняемые компоненты. Системные службы для клиента не устанавливаются. При подключении создаются `yggguard0` и `yggguard-vpn`. Привилегированный компонент следит за связью с окном: при отключении/закрытии сначала возвращает DNS, затем останавливает TUN и Yggdrasil и удаляет свою таблицу nftables. Повторное одновременное VPN-соединение блокируется.

- DNS отправляется через DoH/443 и тот же HTTP-прокси, в том числе в Tor-режиме.
- При работающем systemd-resolved DNS задаётся для VPN-интерфейса. Иначе клиент временно заменяет `/etc/resolv.conf`, сохраняя исходный файл или symlink целиком.
- Незатребованные входящие подключения на `yggguard0` отбрасываются отдельной таблицей `inet yggguard_client`.
- Соединения процессов root исключены из TUN, чтобы Yggdrasil не зацикливался внутри собственного VPN. Это клиент для трафика обычных пользовательских приложений; root-службы могут обращаться напрямую.
- Tinyproxy не передаёт произвольный UDP. Клиент перехватывает DNS, а остальной UDP отклоняет; браузеры обычно переключаются с QUIC на TCP.
- Это не постоянный kill switch. После штатного отключения или завершения движков восстанавливается обычный интернет.

## Восстановление после принудительного завершения

Штатное закрытие восстанавливает настройки автоматически. После `kill -9`, сбоя ОС или внезапного отключения питания проверьте, что процессы клиента уже не работают, прежде чем восстанавливать сохранённый DNS:

```bash
ps -ef | grep -E 'yggguard-helper|yggguard-session'
# Только если активного подключения YggGuard больше нет:
sudo test ! -e /etc/.yggguard-resolv.conf.original || \
  sudo mv -f /etc/.yggguard-resolv.conf.original /etc/resolv.conf
# Только если осталась таблица от прерванного сеанса:
sudo nft delete table inet yggguard_client
```

Не удаляйте чужие сетевые таблицы или маршруты. Если запущен другой VPN или системный Yggdrasil, для первого испытания отключите их, чтобы маршруты не конфликтовали.

## Сборка

Нужны CMake, C++17, Qt6 Widgets/Network, Go 1.24+, Python3 и squashfs-tools. Движки и Type-2 SquashFS runtime передаются упаковщику явно — случайная системная программа не подменяет отсутствующий компонент.

```bash
cd YggGuard/client
bash scripts/build.sh
# Сборка чистых upstream-движков, требует сети:
bash scripts/build-engines.sh
# Упаковка с заранее полученным Type-2 runtime:
python3 scripts/package.py \
  --yggdrasil vendor/yggdrasil \
  --sing-box vendor/sing-box \
  --runtime vendor/runtime-x86_64
```

Для другой системы путь Qt-плагинов задаётся через `--qt-plugins`. Например Ubuntu: `/usr/lib/x86_64-linux-gnu/qt6/plugins`. Runtime должен быть x86_64 и поддерживать SquashFS; runtime только для DwarFS не подходит. В локальную сборку взят runtime из уже имеющегося AppImage PrismLauncher, версия static-tools `55b460f`. Сам PrismLauncher в сборку не входит.

Локальный тестовый AppImage включает Yggdrasil 0.5.15 из установленного пакета и существующий sing-box 1.12.12 из Happ. Версии/контрольные суммы движков включены в `usr/share/yggguard/components.json` внутри AppImage. Лицензии — в `usr/share/licenses`. Исходники и инструкции сборки клиента находятся в этой папке. Для публичного выпуска предусмотрена пересборка движков из исходников, см. `licenses/components.md`.

## Проверки

```bash
ctest --test-dir build --output-on-failure
(cd helper && go test -buildvcs=false ./...)
# Дополнительно проверить реальную схему конфигурации установленным бинарником:
(cd helper && YGG_TEST_SING_BOX=/path/to/sing-box go test -buildvcs=false -count=1 ./...)
```

Проверены компиляция GUI/helper, добавление/удаление и сохранение профилей, отклонение некорректных адресов, конфигурация sing-box реальным движком, восстановление DNS-файла и symlink, запуск GUI из упакованного AppImage без FUSE.

**Полный VPN-сеанс с root, TUN и выходом через VPS ещё не проверен:** среда сборки запрещает сетевые сокеты и создание TUN. Первый запуск на обычном компьютере — обязательный следующий этап проверки.
